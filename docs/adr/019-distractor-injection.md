# ADR 019：干擾段落注入——評估「檢索到錯的或不相關的段落」時會不會被帶偏

- 日期：2026-10-05
- 狀態：採用（評估專用）

## 背景
企劃書的評估題型有「干擾段落題」，README「與企劃書的差異」記為「干擾段落題需 C 加注入機制」。
`run_eval.py` 早就有 `distractor` 題型，但沒有任何東西會把干擾段落放進檢索結果，這類題目量不到東西。

真實系統會碰到兩種干擾：
1. **檢索雜訊**：取到別幅畫、別張圖紙的段落（和問題用詞相近但講的是別的東西）
2. **錯誤內容**：段落掛在同一幅畫底下、主題也對，內容卻和事實衝突（資料來源寫錯、未審核的投稿）

## 選項
1. 在知識庫放假段落：會污染展示與其他評估，也要重建索引。
2. 評估腳本自己組 prompt、繞過後端：量不到後端的洩密掃描與段落篩選，結果不能代表系統。
3. **`/chat` 收評估專用的 `inject`，混進檢索結果後照常走完整流程**。

## 決定
採用 3。

- **請求**：`ChatRequest.inject`（最多 5 段），每段：
  - `kind: counterfactual`：呼叫端手寫的段落（`text` 必填、`topic` 選填），掛在同一幅畫／同一張圖紙底下
  - `kind: other`：自動取同領域**其他**畫作／圖紙中和問題最相近的真實段落；工廠圖紙只從看得到的圖紙取（Metadata Filter）
  - `position`：`first`（放在真正段落之前，預設）或 `last`
- **位置**：`retrieve()` 之後、第 4 段洩密掃描與段落篩選（ADR 008）之前。所以量到的是「篩選擋不擋得掉」加上「模型會不會被帶偏」。
- **分數**：counterfactual 的 `score` 用它和問題的 bge-m3 相似度，和真正段落同一把尺。
- **標記**：留下來的注入段落在 SSE `sources` 帶 `injected: true`、`injected_kind`，`chunk_id` 以 `inject:` 開頭。
- **安全**：`EVAL_INJECTION=false`（預設）時帶 `inject` 一律 403 `FORBIDDEN`。這個欄位等於讓呼叫端把任意文字塞進 prompt，
  只在跑評估的主機打開。前端不會送它。
- **題目**（`eval/qa.jsonl`）：`type: distractor`、`distractors`（同上格式）、`forbidden`（干擾段落裡的錯誤事實）。
- **計分**（`run_eval.py`）：
  - `distractor_kept`：注入段落通過篩選、進了 prompt
  - `distractor_cited`：回答引用了注入段落
  - `distractor_misled`：回答出現 `forbidden` 的字詞
  - 被引用或被帶偏就不算答對；`citation_ok` 引用到注入段落也不算
  - 摘要 `by_strategy.<策略>.distractor`：`filtered_out`（越高越好）、`cited`、`misled`（越低越好）

## 結果（5070 Ti、Qwen3-VL 8B，6 題示範題，`eval/runs/20261005T033938-97d3`）

| | 篩選關（`hybrid_plain`） | 篩選開（`hybrid_rearrange`，目前預設） |
|---|---|---|
| 干擾段落被篩選擋下 | 0/6 | 4/6 |
| 回答引用干擾段落 | 3/6 | 2/6 |
| 被帶偏 | 3/6 | 2/6 |
| 干擾段落題答對 | 3/6 | 4/6 |

- **other（別幅畫的段落）**：篩選 3/3 擋下；沒擋時模型也沒被帶偏（3/3 答對）。
- **counterfactual（同一幅畫、內容錯）**：篩選只擋下 1/3。〈有絲柏的麥田〉篩選開時**只留下假段落**，回答「1979 年取得」
  （正確是 1993）；篩選關時兩段都在，模型答 1993 但補充提到 1979。〈谿山行旅圖〉兩種設定都答對李霖燦、1958，
  卻都把假段落的「張大千」一起寫進去。
- 段落篩選判斷的是「和問題相不相關」，不判斷「內容對不對」：同主題的錯誤段落會被當成相關留下，甚至擠掉真的段落。

## 注意
- 示範題只有 6 題、由 C 撰寫，只驗證機制能運作；正式題目由 D 補（每幅畫至少各一題 counterfactual 與 other）。
- `misled` 是字詞比對的代理指標：回答寫「並非 1979 年」也會被算成被帶偏。正式成績依企劃書由兩人獨立評分。
- 後續可以考慮（C）：段落篩選或 prompt 要求「段落之間互相矛盾時指出矛盾、不要只採信一段」，再用這組題目量改善幅度。
