# ADR 003：工廠機械加工圖領域與 Ortho2CAD 3D 重建

- 日期：2026-09-30
- 狀態：採用（demo）

## 背景
專題定位是「地端部署＋資料隱私」，目標客群包含製造業。畫作是公開資料，說服力有限；
工廠的加工圖、製程與檢驗規範才是真正不能外流的資料。所以用同一套架構（辨識 → 檢索 → 本地生成）
加一個「工廠機械加工圖」知識庫，並加上製造業特有的需求：**把二維三視圖還原成可編輯的 3D 模型**。

## 選項（圖紙 → 3D）
1. 一般 VLM（Qwen3-VL、雲端大模型）直接寫 CadQuery：論文中未微調的開源模型 IoU 明顯較低；雲端違反定位。
2. 傳統演算法（由三視圖做線框重建）：只適合乾淨的向量圖，對照片與隱藏線很脆弱。
3. **Ortho2CAD**（Joglekar et al., arXiv 2607.08891）：Qwen3-VL-8B 以三視圖→CadQuery 微調
   （SFT＋以 IoU 為獎勵的 RL），輸出可執行、可編輯的參數化程式碼。

## 決定
採用 3，並保留 1 當對照組（前端可切換「Qwen3-VL 4B 未微調」）。

- **權重**：論文作者沒有公開權重，使用 Hugging Face 第三方版本並固定 commit（見 `pipelines/setup_ortho2cad.py`）。
  GGUF（Q4_K_M）只含語言模型；訓練時 `tune_mm_mlp=True`，投影層有微調，不能用原版 mmproj，
  所以只以 HTTP Range 下載 `model.visual.*`（1.15 GB）自行轉成 mmproj。
- **推論**：Ollama 目前不能轉 Qwen3-VL 的 safetensors，改用 llama.cpp 的 `llama-server`
  （OpenAI 相容介面，`make ortho2cad`），沿用本專案「本地策略只准連本機／內網」的 provider 檢查。
- **輸入分布**：照官方 `pythonocc_for_step_to_ortho.py` 移植成 CadQuery／OCP 的產生器
  （`app/cad/drawing.py`），知識庫圖紙與「重建結果的回投影」都用它畫；送模型前裁掉標題欄、
  縮到訓練時的 `max_pixels=50176`（224×224）。
- **尺度**：模型輸出 DeepCAD 正規化尺度（約 0–1），依圖紙標註的外形尺寸等比縮放回 mm；
  未收錄圖紙由本地 Qwen3-VL 讀圖上的三個尺寸（兩個模型分工：Qwen3-VL 讀字、Ortho2CAD 建模）。
- **安全**：模型產生的是 Python 程式碼。AST 白名單（只准 cadquery／math、禁底線屬性與匯出入）→
  受限內建函式的子行程（CPU／檔案大小上限、不帶環境變數）→ macOS `sandbox-exec` 禁網路、
  只准寫入工作目錄 → 逾時砍掉。
- **圖紙辨識**：沿用 ADR 002 的兩階段，但圖紙版面都一樣，實測不同圖紙會在標題欄（連材料文字都相同）
  與尺寸數字上對上 300 個以上的點。改為：知識庫圖紙只在三視圖幾何區抽特徵點、排除退化的 homography
  （det≈0 或 >6），再把照片拉正比對線條重合度（F1）。
- **評估指標**：論文的 IoU（質心＋慣性主軸對齊、正規化尺度），另加「不旋轉」候選；體積改用體素計算，
  因為模型產生的實體常有細微瑕疵，OCC 布林交集會默默回傳 0（兩塊幾乎相同的板子算出 0.09）。
  另報「外框對齊 IoU」（重建結果外框對齊到圖紙標註尺寸）當工程上較直觀的參考。
  無效的實體先用 ShapeFix 修復再匯出與計算（未修復時同一份程式碼的 IoU 從 0.73 掉到 0.12），前端標示「已自動修復」。

## 結果（MacBook Air M5 16 GB，模擬實拍照，2026-09-30）
- 圖紙辨識：同圖紙 inlier 41–1376、線條重合 ≥ 0.60；不同圖紙（inlier ≥ 25 者）重合 ≤ 0.48。
  Top-1 100%（30 張，6 張圖紙 × 5 種拍法），未收錄拒答 100%（30 張，含版面相同的 5 張未收錄圖紙與治具定位板）。
- 3D 重建（6 張知識庫圖紙）：Ortho2CAD 可執行率 100%、平均 IoU 0.54（外框對齊 0.71）；
  未微調的 Qwen3-VL 4B 可執行率 17%、平均 IoU 0.07。板件、法蘭、軸承座表現好，
  軸類（車削件）與 T 形截面較弱——訓練資料 DeepCAD 以草圖擠出件為主。逐件數字見 README「評估」。
- 延遲：Q4_K_M 記憶體充足時約 25 token/s、與 Qwen3-VL 同時載入時約 15 token/s；
  一張圖紙 700–3,000 token，約 45–200 秒；前端逐字串流程式碼。

## 注意
- 第三方權重的訓練細節（只有 SFT 或含 RL、哪個資料集）無法確認；報告引用論文數字時要註明不是同一份權重。
- 圖紙與製程文件是虛構的示範資料；模擬照由數位原圖加工。正式評估需真實列印／拍攝的圖紙，
  並重新校正 `drawing_retrieval` 的門檻。
- 16 GB 記憶體同時載入 Ortho2CAD（約 6.5 GB）與 Qwen3-VL 4B 很吃緊；5070 Ti 主機或 32 GB 以上較適合。
