# ADR 034：頁首設定面板——問答開關存在瀏覽器，Jev／地端不做開關

- 日期：2026-10-12
- 狀態：採用（分支 `設定`）
- 編號：033 已由 PR Sinediesoft/art-rag#13（`c/adversarial-eval`，`rearrange_v4`）使用，這份用 034
- 相關：ADR 008（段落篩選）、024（回答附圖）、028（矛盾檢查）、030（伺服器掌握管線）、032（整合版前端）

## 背景
段落篩選、矛盾檢查、回答附圖三個開關，後端早就接受每個請求指定（`ChatRequest.rearrange`／`conflict_check`／`send_image`，
`null`＝伺服器設定），但前端從來沒送過，只能改 `.env` 整台一起換。展示時想當場比較「篩選開／關」、
在 4 GB 顯卡上關掉附圖，都要重啟後端。另外有人想在畫面上切「Jev 還是地端路由」。

## 決定
1. **頁首右上角放「設定」按鈕**（三條滑桿圖示），入口、模組、功能頁三種頁首都有，元件只有一份
   （`components/shell/SettingsMenu.tsx`）。入口原本獨立的深淺色按鈕收進設定（工廠、藝術模組固定深色，面板上有寫）。
2. **三個問答開關各有三態：預設／開／關**。「預設」＝請求不帶這個欄位，照伺服器的 `.env`＞`models.yaml`。
   不做成只有開／關：各主機的預設不同（GTX 1650 和 5070 Ti），開／關會把那台主機的調整蓋掉。
   `/status` 新增 `chat_defaults`（三個布林，`.env` 覆寫後的結果），面板顯示「預設（開）」；每項附代價
   （篩選 GTX 1650 每題多 3–6 秒、矛盾檢查 5070 Ti 首字最多晚 0.6 秒、附圖每題約 1,070 token）。
3. **存在瀏覽器**（`shell/settings.ts`，localStorage `artrag-settings-v1`），不跟帳號走：展示帳號是共用的
   （`access.yaml`，大家預設都是訪客），跟帳號走會讓一個人關掉篩選、所有訪客都被關掉。切換身分不清；
   存不了（無痕、封鎖網站資料）時只在這個分頁生效。設定只是開關的選擇，不含任何資料。
4. **套用範圍**：入口與模組的對話（`shell/runner.ts`）、功能頁的問答（`hooks/useChatStream.ts`）。
   請求本身已指定的欄位不蓋；**策略比較頁固定送 `null`**（只比生成端，不受個人設定影響）。改了從下一題生效。
   回答下方寫「依你的設定：段落篩選 關」，第 4 段軌跡在篩選被關時寫「段落篩選已關：你的設定」，
   同一題前後答案不同時看得出原因。
5. **Jev／地端不做開關**，評估模式也不放在面板上。第 2、4～6 段由誰判斷維持由伺服器決定（ADR 030）：
   `engine=local` 曾讓攻擊句放行；只靠地端規則時 `eval/guard_qa.jsonl` 攔截 7/12，換句話說的攻擊主要靠 Jev Choice。
   要整台不送 Jev（斷網展示）是 `.env` 的 `JEV_ENABLED=false`；評估用的 `engine=local` 照舊只給 `EVAL_CONTROLS`＋本機。
6. **不放進面板**：`models.yaml` 的門檻（共用層，改了要重跑評估）、`MODEL_KEEP_ALIVE`、記憶體管理、雲端 API——都是伺服器層級。

## 取捨
- 三個開關都不影響第 1～7 段安全關卡（後端說明已寫明），所以讓每個人自己調不會降低防護。
- 同一個人換電腦、換瀏覽器要重設；共用的展示電腦上，前一個人的設定會留給下一個人（面板寫著「只存在這個瀏覽器」）。
- 存檔的對話紀錄（`artrag-shell-v1`）不記每題用了什麼設定，重新整理後回答下方的「依你的設定」不會再出現。
- 驗證：`npm test`（`shell/settings.test.ts`、`App.test.tsx`「頁首設定」）、`pytest`（`test_status_reports_chat_defaults_after_env_override`）。
