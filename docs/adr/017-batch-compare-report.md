# ADR 017：批次辨識、兩件並排比較、問答匯出報告——三個兩個領域都用得到的小工具

- 日期：2026-10-03
- 狀態：採用（demo，`feat/批次比較報告`）
- 由來：`問題/專案問題.md` Q-2026-10-02-01 第 4 項（「幾乎零成本的三個」），使用者在 2026-10-03 要求「三項都做，畫作、工廠都要」
  （個人工作流程檔，不在 repo 裡）

## 背景
專案主打「通用型智慧助手」，但每個工具在展示時只在一個領域示範，看起來像專用。
這三個工具都不加新模型：把現有的辨識、知識庫資料、問答結果換成「一次處理很多張」「兩件並排」「帶走」三種用法，
同一個功能在畫作、工廠各示範一次。

| 工具 | 畫作 | 工廠 |
|---|---|---|
| 批次辨識匯出 CSV | 典藏盤點：一次拍整面牆，哪幾幅已建檔、哪幾幅沒有 | 舊圖紙歸檔：一疊照片對回料號與版次 |
| 兩件並排比較 | 兩幅畫的作者、年代、材質、典藏、風格、色彩分析 | 兩張圖紙的料號、版次、材料、外形、體積、重量 |
| 問答匯出報告 | 導覽講稿 | 檢驗紀錄草稿 |

## 決定

### 1. 批次辨識（`POST /api/v1/batch/identify`，SSE；前端 `/batch`）
- 每張照片走以圖搜圖同一套（`search_service.identify_any`：領域路由＋該領域的兩階段辨識）；可以指定只找畫作或只找圖紙。
  只用 Chinese-CLIP 與 ORB，不呼叫生成模型（記憶體管理的流程 `batch_identify`，只標 `clip`）。
- **糊照先擋、不辨識**：和照片建檔同一個指標與門檻（`page.blur_score`、`intake.max_blur: 0.30`）。
  糊照硬判容易對錯，列成「太模糊，請重拍」比給一個看似有把握的答案好。
- **資料範圍逐列處理，不讓整批失敗**：判成工廠圖紙但身分不能用工廠圖紙、或辨識出看不到的圖紙 → 那一列標「目前身分看不到」，
  不回 id（和 `/search/drawing` 回 403 同一個規則）；「最相近」也只列看得到的圖紙。
- 結果一列一列串流（`row`），最後 `done` 附統計；一批上限 `batch.max_images: 100`（每張約 0.6 秒）。
- 前端逐張在瀏覽器轉正、縮圖、去 EXIF 再上傳（`preprocessImage`，和單張上傳相同）；「不在知識庫」那一列可以直接拍照建檔（ADR 013）。
- CSV 在瀏覽器產生：UTF-8 加 BOM（Excel 才不會亂碼）；`= + - @` 開頭的格子前面加 `'`，避免被當成公式執行（CSV injection）。

### 2. 兩件並排比較（`GET /api/v1/compare/items?a=&b=`、`POST /api/v1/compare/summary`；前端 `/compare-items`）
- 表格直接讀知識庫（建索引後的資料），不呼叫模型，毫秒級。每一格附出處：
  知識庫 JSON（畫作另附典藏頁網址）、執行標準模型計算（體積、重量）、照片建檔時確認的圖上標註、色彩分析（建索引時由原圖計算，ADR 010）。
- 只比同一類（兩幅畫或兩張圖紙，`COMPARE_KIND_MISMATCH`）；圖紙照資料範圍（訪客不能用、業務看不到機密 → 403）。
  回應的 `level` 是兩件裡最高的機密等級，匯出時印在頁首。
- 差異摘要（選用，按了才產生）：本地生成端依「比較表的事實＋兩邊各 3 段知識段落」寫一段，引用段落的句子附 [編號]
  （`shared/prompts/compare_v1.md`、`item_compare.*`）。只走 `hybrid` → `hybrid_fallback`（本地），圖紙不送雲端；
  段落先過地端的洩密規則（七段權限控管第 4 段同一組 `guard.local_rules`，`guard.local_leak()`），色彩段落不放（表格裡已有）。
  權限在開始串流前就檢查（看不到 → 403，不是 200 的串流裡夾 error）。
- 和影像比對（ADR 012）互補：那個比「圖上哪裡不同」，這個比「資料哪裡不同」。

### 3. 問答匯出報告（前端；`components/common/QaExport.tsx`、`lib/export.ts`）
- 每一則回答下方「匯出報告／列印／存成 PDF」；畫作問答頁、圖紙問答頁另有「匯出整段問答」（導覽講稿、檢驗紀錄草稿）。
- 單一 HTML 檔（封面圖以 data URL 內嵌，不用另外的檔案）；列印用隱藏的 iframe，不開新視窗。
  內容：問題、回答（[編號] 連到出處）、引用段落全文、出處網址或來源、授權、模型、延遲、外送量、`request_id`。
- 機密等級取引用段落裡最高的一級：內部、機密時頁首印警示；報告結尾註明「草稿，使用前請人工核對」。

### 4. 匯出稽核（`POST /api/v1/exports`）
- 檔案在瀏覽器裡產生，但匯出了哪些資料要留紀錄：三種匯出都先記一筆 `audit_log`（`action: 匯出`、`op: export_<種類>`、涉及的 id、列數），
  記不到（例如憑證過期）就不匯出。涉及看不到的圖紙 → 403（正常操作不會出現，出現了就是繞過畫面）。

### 5. 統一入口（ADR 016）
- `shared/agent.yaml` 新增兩個意圖：
  - `batch_identify`（批次辨識）：對話裡給說明與「打開批次辨識」按鈕；照片在功能頁上一次選一批。
  - `compare`（並排比較）：比較的字眼（比較、差異、有什麼不同…）加上句子裡**兩件同一類的作品**才加分（`local_router.pair()`，`COMPARE_PAIR_BOOST`），
    「這幅畫和同時代作品相比」只提到一件，仍是畫作問答。對話裡先列出前 6 個不同的欄位，「看完整比較表、差異摘要與匯出」打開比較頁。
- 第 1 段：並排比較兩張圖紙時資料領域是 `mfg`，`doc` 取兩張裡機密等級較高的那張——業務比較一張看得到、一張機密的圖紙會降級「查無資料」，
  不透露機密圖紙存在。批次辨識不在第 1 段碰資料，看得到什麼由批次辨識 API 逐列判斷。
- 修改資料的「盤點」關鍵字排除「典藏盤點」「館藏盤點」（`(?<!典藏)(?<!館藏)盤點`），倉庫的盤點仍是修改資料。

## 取捨
- 批次辨識逐張在同一個請求裡跑，100 張約 1 分鐘；使用者離開頁面就中斷，已辨識的列不保存（要保存就匯出 CSV）。
- 比較表只比知識庫裡有的欄位；照片建檔的零件沒有標準模型，體積、重量那兩格寫「未計算」。
- 報告是草稿：4B 模型的回答要人審；CC BY 段落的標示文字要保留。
- 匯出稽核由前端呼叫，伺服器無法保證「記了才匯出」（資料本來就已經在瀏覽器裡）；它記的是正常操作，防不了刻意繞過。
