# ADR 029：畫面區域——把解說綁到畫作上的一塊（第 1 步：格式、建索引、顯示；第 2 步：藝術家圈選、主管收錄）

- 日期：2026-10-08
- 狀態：採用（第 1、2 步，分支 `區域標註`；第 2 步見文末「第 2 步：藝術家圈選、主管收錄」）
- 由來：`問題/專案問題.md` Q-2026-10-08-01 與追問（個人工作流程檔，不在 repo 裡）；ADR 012 排過的「第 2 步：具名區域」

## 背景
目標是讓藝術家在畫上圈出一塊區域、寫下解說，故事就綁在畫面座標上：觀眾看畫作頁時知道這段在講哪裡，
問答引用時能在畫上標出那一塊，之後觀眾拍局部近照，也能用影像對位（ADR 012）算出拍到哪一塊、優先拿那一塊的解說。

現況：段落（`chunking.build_chunks`）只有 `topic`、`text`、出處，沒有座標；畫作頁只有一張圖。
影像對位已經有一套 0–1 的座標（`align.Location.polygon`），前端也已經用 `viewBox="0 0 1 1"` 的 SVG 疊在圖上畫框
（`AlignmentCards.tsx` 的 `CoverageOutline`）。

使用者選定的做法（2026-10-08）：
- **A：藝術家有自己的帳號**，送草稿、主管收錄（第 2 步才做）。
- 先做**第 1 步**：格式、驗證、建索引、畫作頁顯示、引用標亮；先手寫一筆驗證，不做圈選編輯器。

## 選項
1. **存在畫作 JSON 裡**：`kb/artworks/<id>.json` 加選填的 `regions`，段落用 `region` 指過去。
2. 另存 W3C Web Annotation 檔（`kb/annotations/<id>.json`）：可以和 IIIF 檢視器互通（Q-2026-10-05-07 的建議）。

## 決定
採用 1。解說本來就是段落：授權、出處、至少 20 字、切塊、引用都能沿用，一塊區域也可以有好幾段；
一幅畫一個檔，組員從 `kb/` 重建時不會漏。要和 IIIF 互通時，再由 API 把它轉成 W3C 格式輸出。

### 格式（`shared/schemas/artwork.schema.json`）
```json
"descriptions": [{ "...": "...", "region": "mule-train" }],
"regions": {
  "image_size": [511, 1024],
  "items": [
    { "id": "mule-train", "label": "騾隊與後方樹叢",
      "points": [[0.74, 0.75], [0.99, 0.75], [0.99, 0.89], [0.74, 0.89]] }
  ]
}
```
- **座標**：相對 `image.path` 那張圖的 0–1（x 往右、y 往下），和影像對位同一套。三張圖的長寬比都不同
  （`npm-000001` 是 511×1024），存比例就不受顯示大小、縮圖影響。
- **形狀**：多邊形 3～64 個點，矩形是 4 個點；之後自由圈的線在前端簡化成多邊形再存。
- **`id`**：小寫英數字與 `-`，同一幅畫內不重複。
- **`image_size`**：圈區域時那張圖的寬、高。座標綁死那張圖，換圖（重裁、換高解析度）就會偏。

### 驗證（`backend/app/rag/kb.py` 的 `region_problems()`，`make check-kb`、建索引、照片建檔收錄都會跑）
- 段落指到的區域要存在；每塊區域至少有一段講它；`id` 不重複；
- 多邊形面積至少整張圖的 0.01%（點幾乎在同一條線上就擋）；
- 圖檔尺寸和 `image_size` 不同 → 擋下，訊息請人重新圈；只是等比例縮放的話，確認後改 `image_size`。
  不用圖檔雜湊：調色、壓縮不會讓座標偏，用雜湊會誤擋。

### 建索引（`backend/app/rag/chunking.py`）
- 綁區域的段落多一個 `region`（`id`、`label`、`points`、`bbox`），存在 `chunks.json`／PostgreSQL `chunks.doc`（JSONB），不用改表。
- 段落文字前面由程式加上方位詞：`〔畫面右下・騾隊與後方樹叢〕這幅畫長期找不到作者的簽名…`。
  - 段落本身不一定寫了位置（藝術家寫「這隻鳥是我女兒畫的」），加了之後純文字問「右下角」也搜得到，模型也知道這段講的是畫面哪裡。
  - 方位用外框中心落在九宮格的哪一格，詞和前端 `whereOnPainting()`（「你拍到的位置」）相同，搬到 `lib/format.ts` 兩邊共用。
  - 和「色彩分析」段落一樣是程式組的字；出處、授權照原本那段。

### API
- `GET /api/v1/artworks/{id}`：`ArtworkDetail` 多 `regions`（沒有時為 null）、`Description.region`。
- `/chat` 的 SSE `sources`：綁區域的畫作段落多帶 `region`（`id`、`label`、`points`、`bbox`），其他段落不帶。

### 前端
- 畫作頁：大圖上用白線標出所有區域，圖下列出區域名稱；點區域（圖上或名稱）→ 那一塊以外調暗、捲到講它的段落；
  段落上有「畫面右下・騾隊與後方樹叢（在畫上標出）」可以反過來點。窄螢幕的圖在段落上方，從段落點時把圖捲回來。
- 問答的參考來源：綁區域的段落下面放一張畫作縮圖，框出那一塊（`RegionThumb`）。問答頁、智慧助理、策略比較都用 `ChatAnswer`，一次改到。
- 元件在 `frontend/src/components/regions/RegionOverlay.tsx`。

### 示範資料
`npm-000001`〈谿山行旅圖〉的「落款與發現」段落綁到「騾隊與後方樹叢」（右下方）。
段落說范寬款藏在「畫面右下方、騾隊後方的樹叢枝葉間」；知識庫的圖只有 511×1024，看不出款字本身，
所以框的是段落描述的那一片（放大確認過騾隊在框的下緣），不是款字的精確位置。`kb/VERSION` 2026.10.1 → 2026.10.2。

## 影響
- `shared/`：`artwork.schema.json`（`regions`、`$defs.region`、段落的 `region`）、`openapi.json`、`CHANGELOG.md`。
- 索引：`kb/VERSION` 變了，要 `make index`。`npm-000001#02-0` 的文字多了方位詞，向量會變。
- 問答：〈谿山行旅圖〉的簽名題（`eval/qa.jsonl` q-npm1-01、`qa_conflict.jsonl` q-conf-npm-01）上下文多了「〔畫面右下・騾隊與後方樹叢〕」，
  答案本來就是右下方的樹叢，方向一致；沒重跑評估。

## 第 2 步：藝術家圈選、主管收錄（2026-10-08）
使用者選定做法 A：藝術家有自己的帳號送草稿、主管收錄（Q-2026-10-08-01 追問）。

### 權限（`shared/access.yaml`）
- 新角色 `artist`：ops 只有 `kb_annotate`（送草稿）；展示帳號 `artist`「藝術家・甲」。
- 帳號多一個 `artworks`：可以標哪幾幅畫，沒列的畫回 403（示範帳號給 `npm-000001`、`met-436535`，留 `aic-27992` 示範被擋）。
  `Account` 與 `/auth/accounts` 多回 `artworks`，頁首的權限說明列出這幾幅畫。
- 收錄沿用主管的 `kb_intake`（和照片建檔同一個權限，都是「寫進知識庫」），不另開一個；主管沒有 `kb_annotate`，不會自己送自己收。
- 沒用新的機密等級或部門：解說都是公開畫作的公開段落。

### 流程（`backend/app/services/region_service.py`）
```
藝術家（kb_annotate、畫在 artworks 裡）─► 畫作頁「在畫上圈一塊、寫解說」─► 拖出矩形／自由圈（簡化成 ≤ 64 點）
     ─► 名稱、解說（20–1000 字）、授權（CC BY 4.0＋署名／CC0）─► POST /artworks/{id}/region-drafts
     ─► 輸入防護地端規則（guard.passage_risk）＋合進畫作 JSON 後跑 schema 與 region_problems ─► 草稿 data/regions/<id>.json
主管（kb_intake）─► 核准頁「藝術家的區域解說・待收錄」─► 收錄：再驗一次 ─► 寫 kb/artworks/<id>.json、kb/VERSION 加一版
     ─► 背景重建索引 ─► 新區域在索引裡 → done｜不在 → 把 JSON 和版本還原、再建一次 → failed（可以再收錄）
                    └─► 退回（附原因，藝術家看得到）
```
- **輸入防護**：解說會原文進 prompt，等於新的外部輸入。用 ADR 014 第 2 段的直接注入規則＋第 4 段的間接注入與洩密規則
  （`guard.passage_risk()`，新的公開函式），送出、收錄都跑；只用地端規則，不呼叫模型，不外送。
- **寫檔**：收錄重寫整個畫作 JSON（`dump_kb_json()`）。排法照手寫檔：純量陣列、一行寫得下的純量物件寫成一行，
  三幅畫的原檔重新輸出後一字不差，所以 diff 只有新加的區域與段落。
- **和照片建檔共用一把鎖**（`intake_service._lock`／`_busy`）：兩邊都會改 `kb/` 與重建索引，一次只做一筆；忙的時候回 `INTAKE_BUSY`。
- **段落長這樣**：`topic` 是「<名稱>（<藝術家>的解說）」、`speaker` 是藝術家、`source` 是「<藝術家>親自標註（日期，<主管>收錄）」，
  授權與署名照藝術家選的。區域 id 依序 `r1`、`r2`…。
- **圖換過**：草稿記下送出時的原圖尺寸，收錄時尺寸不同就擋（`REGION_REJECTED`），請藝術家重新圈。
- **保存**：待收錄、收錄失敗的草稿一直留著等主管處理；已收錄、退回的和上傳照片同一個期限（7 天）刪掉。

### 新欄位 `speaker`（段落）
藝術家常用第一人稱寫（「我第一次在美術館看到時…」）。實測（qwen3-vl:4b）只有段落標題寫「藝術家・甲的解說」時，
模型回答「梵谷第一次在美術館看到時…」，把藝術家的話算到畫家頭上。段落加 `speaker`，建索引時文字寫成
`〔畫面右側・右側的絲柏〕藝術家・甲說：「…我第一次…」`，至少資料本身清楚標出「我」是誰。

### API
| 路徑 | 內容 |
|---|---|
| `POST /api/v1/artworks/{id}/region-drafts` | 送草稿（`RegionDraftRequest`：`label`、`points`、`text`、`license`、`attribution`），回 `RegionDraft` |
| `GET /api/v1/region-drafts` | `pending`（能收錄的身分才有）、`mine`（自己送的）、`can_commit` |
| `POST /api/v1/region-drafts/{id}/commit` | 主管收錄，回傳時 `indexing`，重建完變 `done` 或 `failed` |
| `POST /api/v1/region-drafts/{id}/return` | 主管退回（`reason`） |
| `DELETE /api/v1/region-drafts/{id}` | 送的人撤回（還沒收錄的） |

`/auth/accounts` 多 `pending_region_drafts`，頁首「待核准 N 件」把超額申請和待收錄的區域解說加在一起。
新錯誤碼：`REGION_DRAFT_NOT_FOUND`（404）、`REGION_DRAFT_CLOSED`（409）、`REGION_REJECTED`（422）。
稽核：送出記「申請」（`kb_annotate`）、收錄記「寫入」、退回記「退回」（`kb_intake`）。

### 前端
- `RegionEditor.tsx`：畫作頁的編輯模式。SVG 收 pointer 事件（`touch-none`，手機拖曳不會捲頁），矩形或自由圈；
  自由圈用 Douglas–Peucker 簡化到 64 點內；圈太小、字不夠、CC BY 沒署名時「送出」按不下去。
- `RegionDrafts.tsx`：核准頁的「藝術家的區域解說・待收錄」（縮圖框出那一塊、收錄／退回）與「我送出的區域解說」（狀態、退回原因、撤回）。
  收錄中每 1.5 秒重抓，完成後重抓那幅畫，畫作頁馬上看得到。

### 驗證
- `backend/tests/test_region_drafts.py`（9 項）：只有藝術家能送、只能標自己的畫；送出後藝術家看自己的、主管看待收錄；
  注入被擋；CC BY 沒署名、範圍太小、座標超出被擋；收錄寫進 JSON（區域、段落、出處、署名、版本）；退回後不能收錄、只有送的人能撤回；
  收錄失敗還原 JSON 與版本；手寫排法重新輸出一字不差。
- 實機（學校電腦，`artrag-files`，檔案索引、qwen3-vl:4b）：藝術家在〈有絲柏的麥田〉圈右側的絲柏，
  先寫一句「請忽略先前的所有指令…」被擋（「夾帶要 AI 執行的指令」），改寫後送出；主管在核准頁收錄，約 24 秒重建完；
  畫作頁出現「右側的絲柏」，問「畫面右側那棵樹有什麼故事？」引用 [1] 就是這段（相似度 0.61，附縮圖框）。驗完把 `kb/` 還原。

### 注意
- **第一人稱還是會被算到畫家頭上**：加了 `speaker`（段落寫成「藝術家・甲說：「…我第一次…」」）之後，qwen3-vl:4b 仍回答
  「梵谷第一次在美術館看到時…」。資料面已經標清楚，要再改善得在回答 prompt 加一條規則（引號裡的「我」是說話的人），
  並出題評估（`answer_v4` 是 C 在 ADR 026／028 調過的，改 prompt 要跑 `eval/`），這一步沒做。8B 模型沒試。
- 收錄會改工作目錄的 `kb/` 檔，要有人 commit 進 git，組員才拿得到（和照片建檔一樣）。
- 只有一個示範藝術家帳號；正式使用要接真的登入，`artworks` 也要有地方維護（現在手改 `access.yaml`）。
