# ADR 045：帳號密碼登入（JWT 第 1 段多一個取得憑證的方式）

- 日期：2026-10-28
- 狀態：採用（分支 `登入帳密`）
- 相關：ADR 015（七段權限控管、JWT）、ADR 030（展示模式只開在本機）、ADR 036（展示帳號精簡）

## 背景

- 到 2026-10-27 為止，憑證只有兩種來源：`GET /auth/accounts` 沒有憑證時發一般員工的，以及展示模式（`DEMO_CONTROLS=true`＋本機）`POST /auth/switch` 不用密碼切換任何帳號。
- 展示與口試要看到「登入」這一步：關掉展示模式後，畫面上沒有任何方式換成主管、倉管。
- 2026-10-24 的建議是不要做假的帳密登入、正式版接 SSO（`問題/專案問題.md` Q-2026-10-24-03）；這次的目的不同：要有登入畫面，不是要上正式環境（`問題/登入帳密-問題.md` Q-2026-10-27-02）。

## 決定

- **只多一條取得憑證的路，不改驗證**：`POST /auth/login`（帳號＋密碼）驗過就用原本的 `identity.issue()` 簽 JWT、寫進同一個 HttpOnly cookie。`jwt.decode()`、API 閘道、第 2～7 段都不動：它們吃的是用 `sub` 回 `access.yaml` 重查的帳號，帳號是密碼證明還是展示切換證明沒有差別。
- **密碼雜湊放 `.env`**：`ACCOUNT_PASSWORD_HASHES={"manager":"scrypt$...", ...}`，每台自己設定，不進 git。`shared/access.yaml` 會進 git，雜湊放那裡等於公開給組員和 GitHub，可以離線暴力猜。
  - 雜湊用標準函式庫 `hashlib.scrypt`（N=2^14、r=8、p=1，16 位元組隨機鹽），比對用 `hmac.compare_digest`；和 `jwt.py` 一樣不另裝套件。
  - 產生雜湊：`cd backend && uv run python -m app.core.passwords`（輸入兩次、至少 8 個字元，印出一行 `scrypt$...`）。
  - 沒列到的帳號不能用密碼登入；`/auth/accounts` 回 `login_accounts`，前端只列這些。
- **沒登入維持一般員工**：不改 `/auth/accounts` 的行為。`POST /auth/logout` 直接改發一般員工的憑證（不是清成沒有憑證），一次往返就回到原狀。
- **展示模式的免密碼切換保留**：展示時「切換成〇〇再試一次」、`conftest.as_account()`、`eval/` 的腳本都靠它；`DEMO_CONTROLS` 一樣預設關閉。
- **JWT 加 `amr`**：`["pwd"]`＝密碼登入、`["demo"]`＝展示切換、`[]`＝預設的一般員工。只給頁首顯示「密碼登入／展示切換／未登入」，權限不看它。
- **防猜密碼**：
  - 同一個帳號＋來源 IP 連續錯 `LOGIN_MAX_FAILURES`（5）次，暫停 `LOGIN_LOCK_S`（300 秒），回 429 `LOGIN_LOCKED`；暫停時連正確的密碼也不收。成功就清掉計數。
  - 帳號不存在、沒設密碼、密碼錯都回同一個 401 `LOGIN_FAILED`「帳號或密碼不對」，而且都算一次 scrypt（`passwords.DUMMY_HASH`），回應內容與時間都不透露哪些帳號能登入。
  - 失敗寫進第 1 段的拒絕並記錄（規則「登入失敗」：帳號、來源），不記密碼。
- **`/auth/login` 放進閘道的 `PUBLIC_PATHS`**：憑證過期也能直接登入，不用先拿一張一般員工的；`/auth/logout` 照樣要憑證（過期時前端會先重新取得再重送）。
- **前端**：頁首身分選單加登入表單（帳號下拉、密碼）；密碼登入後改顯示「登出」；和切換身分共用同一套流程（`useChangeIdentity`），舊身分還在跑的請求中止、身分相關的快取清掉。開發者平台（`developer-workbench.html`）這次不改。

## 不採用

- **正式版的 SSO（OIDC）**：這次目的是展示，沒有公司身分提供者可接；正式版仍建議接 SSO，到時拿掉 `/auth/switch` 與自建的帳密，第 2～7 段不用改。
- **雜湊放 `shared/access.yaml`**：會進 git。
- **雜湊放資料庫、畫面上改密碼**：要多做帳號管理功能，展示用不到。
- **bcrypt／argon2 套件**：要多一個相依；scrypt 在標準函式庫就有，強度足夠。
- **一律先登入**：`/auth/accounts` 不再自動發憑證，前端每個入口都要處理沒登入，改動大很多；一般員工本來就只能查公開資料。
- **拿掉展示切換**：評估腳本、測試、展示腳本都要改成帶密碼。

## 取捨與限制

- 失敗次數存在單一後端行程的記憶體：重啟就清空；多台後端要改放 Redis（和交接票一樣）。
- 鎖的是「帳號＋來源」：換 IP 可以繼續猜；展示版只在本機或區網，夠用。
- 沒有 HTTPS 時，從別台電腦經區網登入，密碼是明文傳送；本機 `127.0.0.1` 展示沒有這個問題。cookie 也還沒加 `Secure`（Q-2026-10-22-03 第 3 項）。
- 沒有撤銷：登出只是換掉這個瀏覽器的 cookie，已經發出去的憑證在 `JWT_TTL_MIN`（8 小時）內仍然有效。
- 憑證過期或後端重啟（`JWT_SECRET` 留空）時，前端照舊自動改回一般員工，提示「憑證過期，請重新登入」。

## 驗證

- `backend/tests/test_auth.py`：雜湊來回與格式錯誤、沒有憑證／憑證過期都能登入、三種失敗回同一句話且不記密碼、鎖定與解鎖、登出回一般員工、展示切換的 `amr`。
- `frontend/src/App.test.tsx`「帳號密碼登入（ADR 045）」：沒開展示模式時只有登入表單、密碼錯顯示後端訊息並清空密碼欄、登入後顯示「密碼登入」與登出。
