# ADR 018：畫作卡推測（知識庫沒有這幅畫時，推測風格大類、題材、媒材）

- 日期：2026-10-04
- 狀態：採用（demo）
- 編號：017 已被 `feat/批次比較報告`（批次辨識、並排比較、匯出報告）使用，那條分支還沒合進 `dev`，所以這份用 018

## 背景
以圖搜圖辨識失敗時，現在只回「知識庫中沒有這幅畫」，再附色彩分析（ADR 010）和「拍照建檔」（ADR 013）。
不硬湊答案是對的（ADR 002），但觀眾在美術館拍了一幅沒收錄的畫，得到的資訊只有顏色。

ArtSeek（Fanelli、Vessio、Castellano，arXiv:2507.21917，程式 MIT，`cilabuniba/artseek`）先用分類網路 LICN
替畫作產生一張「畫作卡」（畫家、流派、風格、媒材、標籤），再交給 32B 多模態模型。它在 ArtGraph 上的畫家／流派／風格
top-1 是 71.8／78.5／69.8。整套搬過來不行：LICN 依賴 ColQwen2 的嵌入，系統要 64 GB GPU、128 GB RAM、310 GB 向量庫，
和 16 GB 地端展示機的定位衝突（ADR 006、009）。值得借的是「沒收錄的畫也給一張畫作卡」這件事（問答 Q-2026-10-04-03 第 1 項）。

範圍：
- 推測風格（含年代）、題材、媒材，**不推測畫家**：猜錯畫家等於替別人的作品掛錯名字，比留白傷信任；
- 只在辨識失敗時給（以圖搜圖頁、智慧助理）；辨識成功時看知識庫記載就好；
- 結果標明「推測・沒有出處」，**不寫進知識庫、不放進問答的 prompt**——不能讓沒有出處的推測變成回答裡帶 [n] 的「事實」。

## 選項
1. **用辨識已經載入的 Chinese-CLIP 做零樣本分類**：每個標籤寫成幾句中文提示，和照片比相似度。不用訓練、不載入新模型、
   照片不出站；新增或修改標籤只要改 `models.yaml`。缺點：細分類別分不清（見下方「校正」）。
2. 用 ArtSeek 的 LICN（`cilabuniba/artseek-licn`）：準確度有論文數字，但要多載 ColQwen2（約 2B 參數），
   16 GB 機器要和 Qwen3-VL、bge-m3 搶記憶體；標籤是英文的 ArtGraph 類別，還要對譯。
3. 讓本地 Qwen3-VL 看圖描述風格：最省事，但結果無法驗證、每次可能不同，正好違反防幻覺的主軸（和 ADR 010 不用模型目測顏色同理）。
4. 用 Chinese-CLIP 向量訓練一個線性分類頭：要有標好的訓練資料（例如 iMet、WikiArt），demo 階段沒有。
   （後來用大都會館藏做了，媒材改用這個，見「線性分類頭」。）

## 決定
採用 1。之後有標好的資料時，可以拿同一份 `eval/style_truth.json` 和選項 4 比。媒材後來改用選項 4（見「線性分類頭」）。

### 流程
```
以圖搜圖辨識失敗（畫作） ─► GET /images/{image_id}/style ─► 照片 CLIP 向量
   ─► 把關：像畫作的提示 vs 生活照、截圖、文件、圖紙的提示 ─► 不像畫作 → 不推測（fields 為空）
   ─► 三欄零樣本：風格（細分流派 → 大類＋年代）、題材、媒材 ─► 畫作卡（推測・沒有出處）
智慧助理附照片、辨識不到、領域路由判成畫作（photo.domain = "art"）─► 回覆裡同一張卡
```

### 計算（`backend/app/analysis/style.py`）
- **標籤向量**：每個標籤的「別名 × 提示句」各算一個 Chinese-CLIP 文字向量，再平均、正規化（prompt ensembling）。
  別名只用來算向量、不顯示；風格的別名附代表畫家（「梵谷、塞尚、高更的後印象派」），讓描述具體一點。
  約 250 句，CPU 約 5 秒：啟動時在背景先算好、依設定內容的 hash 快取，CLIP 被記憶體管理卸載也不用重算。
- **機率**：softmax(temperature × 餘弦相似度)，temperature＝Chinese-CLIP 的 logit_scale（100）。
- **風格以大類為主**：大類取**細分第一名所屬的那一類**，信心是那一類所有細分流派的機率加總。
  不直接比各大類的加總：「現代藝術」有 6 個流派，長尾的機率加起來會蓋過真正的那一類
  （秀拉〈大碗島的星期天下午〉：細分第一名新印象派 0.33，但現代藝術加總 0.53）。
- **看不太出來**：每欄第一名（風格看大類）低於 `min_confidence` 0.4 就標「看不太出來」，總結句不寫那一欄。
- **把關**：像畫作的 5 句提示 vs 其他 6 句（生活照、螢幕截圖、文字文件、工程圖紙、商品照、自拍）的 softmax，
  畫作那幾句加總低於 `painting_min` 0.6 就不推測。

### 設定（`shared/models.yaml` 的 `style_guess`，不影響索引，改了不用重建）
```yaml
style_guess:
  method: clip-zeroshot-v1
  temperature: 100
  painting_min: 0.6
  painting_prompts: [一幅畫, 一件繪畫作品, 一幅油畫, 一幅中國畫, 一幅版畫]
  other_prompts: [一張生活照片, 一張螢幕截圖, 一份文字文件, 一張工程圖紙, 一張商品照片, 一張自拍照]
  min_confidence: 0.4
  style: {templates: [...], groups: [{name, period, labels: {流派: [別名...]}}]}   # 7 大類、18 流派
  genre: {templates: [...], labels: {...}}                                       # 12 種題材
  media: {templates: [...], labels: {...}}                                       # 8 種媒材
```

### API 與畫面
- `GET /api/v1/images/{image_id}/style` → `StyleGuess`：`is_painting`、`painting_score`、`fields`（風格、題材、媒材各一，
  含前 3 名候選；風格多 `period`、候選帶所屬大類）、`summary`、`notes`、`latency_ms`。
- `/agent/route` 的 `photo` 多 `domain`（`art`／`mfg`）：辨識不到時前端靠它分辨是沒收錄的畫作還是圖紙。
  照片判成沒收錄的畫作時，記憶體管理的預估把 CLIP 列為保留，前端接著推測不必重新載入。
- 以圖搜圖頁：「知識庫中沒有這幅畫」下面接畫作卡；智慧助理：辨識不到的回覆裡接同一張卡。

## 線性分類頭（`make style-head`，2026-10-04【我的筆電】，`iMet` 分支）
問答 Q-2026-10-04-04 第 3 項，也就是上面的選項 4：有了大都會的標籤，拿 Chinese-CLIP 照片向量訓練分類頭，和零樣本比。

### 做法（`pipelines/train_style_head.py`）
- **訓練資料**：`eval/met_train.json`（`make_met_set.py --train`）共 2,010 幅，和評估集、知識庫裡的畫（met-436535）都不重疊。
  - 三類畫作：歐洲繪畫 900、美國繪畫 200、中國畫 250、浮世繪 200。
  - 評估集裡太少的媒材另外補：水彩 150、素描 150、粉彩 100、濕壁畫 60（後三者用媒材欄篩，搜尋結果很雜）。
  - 有題材正解的 1,222 幅、有媒材正解的 1,901 幅。
  - 正解規則補一條：西洋的 pen and ink、ink wash 算素描，不算水墨畫（水墨畫指東亞水墨）。評估集的正解不受影響（`--relabel` 前後 `cmp` 相同）。
- **方法**（iMet 比賽的主流做法）：多標籤，每個標籤一個 L2 正則化的 logistic regression。
  - 照片向量先標準化；每個標籤 512 個權重＋1 個偏差，整個檔案 42 KB，不是新模型、不多佔記憶體（ADR 006）。
  - 正則化強度用 5 折交叉驗證的 out-of-fold log loss 選，兩欄都選 λ = 0.01。
  - 每個標籤的門檻用 out-of-fold 機率依 F0.5 調：比賽用 F2（偏重找全），畫作卡寫錯比漏寫傷信任，所以偏重準確。
  - 過門檻的標籤都列出（可以同時是油畫和蛋彩畫）；沒有任何標籤過門檻就標「看不太出來」。
- **比較**：同一套判分、不經過把關，共四組資料：
  - 大都會評估集；
  - 大都會評估集做成的模擬照（`make_synthetic_photos.py` 的傾斜、反光、裁切、偏暗、模糊輪流套）；
  - 自己的 10 幅原圖、25 張模擬照。

### 決定
- **媒材改用分類頭**（`style_guess.head.fields: [media]`）：

## 後果
- 好處：沒收錄的畫也有東西可看，不用新模型、不出站；標籤與提示句都在 `models.yaml`，組員可以自己調、用 `make eval-style` 驗。
- 限制：
  - 細分流派不可靠；正解只有 10 幅畫、館方沒有流派標籤，細分流派仍然沒有大型評估。
  - 媒材改用線性分類頭後，大都會評估集第一名 291/298，但粉彩畫、蛋彩畫找全低；題材的分類頭要等有風俗畫、城市街景的標註。
  - 把關擋得下雕塑、陶瓷、器物（184/190），但生活照沒有大型評估。
  - 大都會的圖是棚拍的，觀眾拍的照片多了反光、傾斜、牆面，數字會比這裡差。
- 推測結果只在畫面上，不進知識庫、不進問答的 prompt；之後若要讓問答引用，必須另外決定出處怎麼標。
