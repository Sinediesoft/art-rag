# ADR 025：Ollama 模型閒置多久才卸載（MODEL_KEEP_ALIVE）與開機預熱

- 日期：2026-10-07
- 狀態：採用（每台主機用 `.env` 決定；預設不變）

## 背景
Ollama 預設模型閒置 **5 分鐘**就卸載。展示時中間停一陣子，下一位訪客的第一題要等模型重新載入。
5070 Ti（Qwen3-VL 8B）實測 `/chat` 首字：

| | 首字 |
|---|---|
| 模型已載入 | 約 1.5 秒（後端記錄） |
| 閒置被卸載後的第一題 | **6–16 秒**（模型檔還在系統快取約 6 秒；不在時約 16 秒） |

超過驗收目標「首字 ≤ 3 秒」。開機後的第一題也一樣慢。

## 決定
- 新設定 `MODEL_KEEP_ALIVE`（`.env`，例如 `60m`；留空＝不送，用 Ollama 預設 5 分鐘）。
  後端每次呼叫 **Ollama 提供的本地策略**（`hybrid`、`hybrid_fallback`、`lora`）時在請求裡帶 `keep_alive`。
  Ollama 的 OpenAI 相容介面接受這個欄位（實測 `/api/ps` 的到期時間變成 60 分鐘後）。
  不改 Ollama 的全域設定，也不影響同一台 Ollama 的其他使用者。
- 不送給 Ortho2CAD（llama-server router 模式自己管載入，ADR 006）與雲端對照組。
- `deploy/windows/start-services.ps1` 啟動後預熱主力模型（`/api/generate` 只帶 model 與 keep_alive），開機後第一題不用等載入。
- **記憶體吃緊時照樣卸載**：記憶體管理（ADR 006／021）用 `keep_alive=0` 釋放閒置模型，不受這個設定影響。

## 結果（5070 Ti）
- 預熱與一般問答之後，`/api/ps` 的到期時間都是 60 分鐘後。
- 實測時 OBS 佔著數 GB 顯示記憶體，VRAM 91.5% 超過門檻，記憶體管理照樣把閒置的 8B 卸載——
  這是預期的優先順序：keep_alive 只避免「沒必要的」卸載，真的不夠用時還是讓位。
  所以**展示時請關掉其他吃顯示記憶體的程式**，keep_alive 才有效。

## 注意
- 16 GB 統一記憶體的 Mac 不建議設太長：模型常駐會讓記憶體管理更常觸發。
- 組員經 Tailscale 連 5070 Ti 時，是組員的後端帶 keep_alive；這台的記憶體管理不會替遠端請求卸載（ADR 006）。
