# ADR 039：知識庫目錄題——清單題直接列出、比較題附知識庫目錄

- 日期：2026-10-14
- 狀態：採用（`backend/app/agent/catalog.py`；`shared/agent.yaml` 的 `catalog`）

## 背景
網頁上問「目前知識庫有哪些畫」：
- 本地分流沒有任何關鍵詞命中，基準分 0 的「批次辨識」反而第一（28%），先請使用者選
- 選了畫作問答也答不對：問答只檢索和問題最像的幾段，本來就列不出「全部有哪些」。
  「知識庫裡有哪些畫作？」列出段落裡順帶提到、不在知識庫的〈早春圖〉〈萬壑松風圖〉，漏掉〈大碗島的星期天下午〉；
  「目前知識庫有哪些畫」直接「查無資料」
- 比較題「哪幅畫最早完成？」被「哪幅」分成以文搜畫，前端只列搜尋結果；
  「〈有絲柏的麥田〉和〈大碗島的星期天下午〉哪一幅先完成？」只鎖第一個畫名，看不到另一幅的年份，答「沒有資料」

## 決定
1. **清單題直接列出**（`list_pattern`）：整句只是「（知識庫／館藏）有哪些畫、總共幾幅、列出所有作品」時，
   第 2 段放行後回 `short_circuit`（`kind: catalog`），從知識庫列出每幅的作者、年代、媒材、尺寸、收藏；
   不檢索、不呼叫 LLM、不外送，意圖記成畫作問答、閘門 direct（不再先請使用者選）。
   帶條件的（「有哪些畫是在戶外寫生完成的？」「梵谷有哪些作品」）不算，照常交給分流與問答
2. **比較題附知識庫目錄**（`compare_pattern`：最早、最大、哪一幅先…、比較、排序）：沒指定畫作的問答，
   參考資料最前面多一段系統產生的「知識庫目錄」（`chunk_id: catalog`，`level: 公開`，和色彩分析段一樣沒有網址），
   照常經過第 4～6 段，由模型比較並標出處
3. 比較題的分派：被分成以文搜畫時改成畫作問答；句子裡有兩幅以上畫名時不鎖第一幅；
   沒指定畫作時 `dispatch.global_qa = true`，前端直接全庫問答（原本沒帶畫作的畫作問答會改列搜尋結果）。
   使用者自己點以文搜畫時照他選的
4. 前端快速回覆的說明依 `short_circuit.kind` 區分閒聊與目錄題

## 結果（5070 Ti、Qwen3-VL 8B Q4、Jev 開）
| 問題 | 之前 | 之後 |
|---|---|---|
| 目前知識庫有哪些畫 | 請使用者選；選畫作問答後「查無資料」 | 直接列出 3 幅（作者、年代、尺寸、收藏） |
| 知識庫裡有哪些畫作？ | 列出不在知識庫的〈早春圖〉、漏掉〈大碗島〉 | 同上 |
| 哪幅畫最早完成？ | 以文搜畫，只列搜尋結果 | 〈谿山行旅圖〉（北宋），引用目錄段 |
| 知識庫裡哪一幅畫的尺寸最大？ | — | 〈大碗島的星期天下午〉207.5 × 308.1 公分 |
| 〈麥田〉和〈大碗島〉哪一幅先完成？ | 只鎖〈麥田〉，答「沒有資料」 | 見下方實測 |

智慧助理分流評估（`make eval-route`）與 ADR 038 的認畫評估見 CHANGELOG 該列。

## 已知限制
- 清單題的樣式是嚴格比對整句，換一種說法（「館裡收了什麼畫啊」）可能不命中，會照原本的分流走
- 比較題的答案仍由模型產生，偶爾會多寫一句不必要的補充或「知識庫中沒有…」
- 知識庫畫作變多時，目錄段會變長；到幾十幅以上要改成只列和問題有關的欄位
