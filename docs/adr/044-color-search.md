# ADR 044：依色彩找畫（以文搜畫照色彩分析排序）

- 日期：2026-10-24
- 狀態：採用
- 推翻：ADR 010「不在範圍內：依色彩找畫」那一項（ADR 010 其他決定不變）
- 相關：ADR 010（色彩分析）、ADR 014（本地分流）

## 背景

- 使用者在入口打「我想找暖色系的圖」，被分到工廠模組的圖紙查找（`問題/專案問題.md` Q-2026-10-23-16）。分流的修正另見 `shared/CHANGELOG.md` 2026-10-23：`drawing_search` 不再單用「圖」，`art_search` 加顏色詞。
- 分流修好之後，以文搜畫還是看不懂顏色：
  - `search_text()` 只用 Chinese-CLIP 與 bge-m3 的語意分數。
  - 依 ADR 010，「色彩分析」段落刻意不參與排名。
  - 實測「我想找暖色系的畫」：最暖的 npm-000001（暖色 47%、冷色 0）排最後。
- ADR 010 當初不做的理由是「知識庫只有 3–5 幅，展示效果有限」。但使用者真的會這樣問，而且色彩分析的數字建索引時就算好了，排序不需要新模型，也不用重建索引。

## 決定

### 1. 問句提到冷暖、明暗、彩度時，以色彩分析為主排序

`backend/app/services/search_service.py` 的 `search_text()`：

- `color_criteria()` 看問句裡有沒有 `shared/models.yaml` 的 `color_search` 列的詞。每個準則都從色彩分析（`colors`）取一個 0～1 的值（`COLOR_METRICS`）：

| 鍵 | 名稱 | 詞（節錄） | 值 |
|---|---|---|---|
| `warm` | 有色部分暖色 | 暖色、偏暖、溫暖 | 暖 ÷（暖＋冷） |
| `cool` | 有色部分冷色 | 冷色、偏冷 | 冷 ÷（暖＋冷） |
| `light` | 亮調 | 明亮、亮色、淺色 | 亮調占比（L\* ≥ 60） |
| `dark` | 暗調 | 暗色、偏暗、深色 | 暗調占比（L\* < 30） |
| `vivid` | 高彩度 | 鮮豔、濃烈 | 高彩度占比（C\* ≥ 25） |
| `muted` | 低彩度 | 素雅、淡雅 | 低彩度占比（C\* < 10） |

- 一句提到好幾個準則就取平均。結果照這個分數排，RRF 的語意分數只用來排同分的。沒有色彩分析的畫排在最後。
- 問句沒有這些詞時，排序和以前完全一樣。

### 2. 冷暖只比有色部分

- 用暖色占整張圖的比例，3 幅分別是 47%、24%、24%，後兩幅只差 0.01 個百分點；黑白灰多的畫（水墨、點描）還會被拉低。
- 改成暖 ÷（暖＋冷）之後是 100%、56%、39%，分得開。中性色本來就不算冷也不算暖，不該影響「偏暖還是偏冷」。

### 3. 回應帶排序依據

`TextSearchResponse` 新增兩個選填欄位，舊的用法不受影響：

- `color_sort`：問句對到的準則（`key`、`label`、`term`）。
- 每筆的 `color`：`score` 和 `detail`（例如「有色部分暖色 56%」）。

前端在三個地方標出「依色彩分析排序」和每幅的依據：
- 對話裡的回答
- 展示區的搜尋結果：這時不畫語意分數條，因為它不是排序依據
- 搜尋頁

### 4. 分流與排序的詞要一致

`shared/agent.yaml` 的 `art_search` 有一條顏色詞關鍵字（權重 1.5）。測試 `test_color_terms_are_routed_to_art_search` 檢查 `color_search` 的每個詞都會先被分到以文搜畫。

## 不做

- **不建色調標籤**：色彩分析的數字已經在 `artworks.doc.colors`（PostgreSQL）／`data/index/artworks.json`，直接用。
- **不改段落檢索**：「色彩分析」段落照舊只給問答用，避免同一份數字在語意分數和色彩分數裡各算一次。
- **不篩選**：只有 3 幅畫，設門檻很容易一幅都不剩；全部留著、照分數排、標出比例。
- **不處理否定與內容詞的組合**：「不要太暗」照樣當成要暗；「暖色調的山水畫」以顏色為主，不會先把山水畫排前面。畫多了再考慮把色彩分數併進 RRF。

## 影響

- `GET /api/v1/search/text`：多了 `color_sort`、`results[].color`（`shared/openapi.json`、`frontend/src/api/schema.d.ts` 已重新產生）。
- 智慧助理分流到以文搜畫時（`/agent/route` → `art_search`）一樣適用。
- 不影響索引，改 `color_search` 不用 `make index`；改 `color_analysis` 照 ADR 010 要重建。
