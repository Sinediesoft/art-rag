# ADR 016：前端統一入口——七段流程分派功能，「深入」按鈕才打開功能頁

- 日期：2026-10-03
- 編號：原 ADR 014，2026-10-03 合併 `dev` 時改號——012 是 `dev` 的影像對位（`012-image-alignment-compare.md`）、013 已被 `feat/照片建檔` 的 `013-photo-intake.md` 使用
- 狀態：採用（demo，`d-rag`）；只改前端，API、`shared/agent.yaml`、七段權限控管（ADR 015）都不變
- 來源：使用者要求「前端介面不再讓使用者做畫作、圖紙、3D 建模等功能切換；統一在智慧助理輸入，經由七段流程判斷
  需要引用哪一功能；對話框給出結果的同時給一個按鍵，讓使用者決定是否深入了解或使用相關功能」

## 背景
頁首導覽列有 7 個分頁（智慧助理、尋畫、工廠圖紙、庫存查詢、生產排程、策略比較、系統狀態），手機版在底部。
使用者得先自己判斷問題屬於哪個功能、切到那一頁再問；七段權限控管裡「交給哪個功能」這一步（本地分流＋Jev Choice）
只有在智慧助理頁才派上用場，其他分頁等於各自一個入口。

## 決定

1. **首頁就是智慧助理**：`/` 是對話（`/assistant` 轉址到 `/`）；導覽列與手機底部分頁列拿掉，頁首只留品牌、
   服務狀態、記憶體標示與身分列。尋畫首頁（`HomePage`）與工廠圖紙首頁（`DrawingsHomePage`）移除，`/drawings` 轉址到 `/`。
2. **功能頁保留，但只從對話進去**：畫作頁、問答頁、以文／以圖搜尋結果、圖紙頁、3D 重建、庫存查詢、生產排程、
   主管核准、系統狀態都還在；介面上只從回答下方的「深入」按鈕（或功能頁彼此之間的連結）進去，
   上方固定一列「‹ 回到智慧助理 · 深入：〇〇」。策略比較是生成端的對照實驗，從系統狀態頁右上進去。
3. **結果先出現在對話裡，按鈕讓使用者決定要不要深入**（`frontend/src/pages/AssistantPage.tsx` 的 `deepActions()`）：

   | 七段流程分派到 | 對話裡直接給的結果 | 「深入」按鈕 |
   |---|---|---|
   | 以文搜畫 | 前 3 名畫作卡 | 看完整搜尋結果 |
   | 畫作問答 | 串流回答＋出處 | 打開〈畫名〉、繼續問這幅畫 |
   | 圖紙查找 | 前 3 張圖紙卡 | 打開〈圖紙〉（有指定時）、看完整查找結果 |
   | 圖紙／製程問答 | 串流回答＋出處 | 打開〈圖紙〉、繼續問這張圖 |
   | 庫存・訂單・工單查詢 | SQL、結果表、回答 | 打開庫存・訂單・工單查詢 |
   | 3D 重建（要確認） | 要轉哪一張、耗時與記憶體說明、圖紙卡 | 開始 3D 重建、先看圖紙與之前的重建結果 |
   | 排程求解（要確認） | 待排工單數、現行排程準時率 | 打開生產排程 |
   | 修改資料 | 試算、確認卡、送主管核准（不變） | 打開庫存查詢或生產排程核對 |
   | 系統狀態 | 記憶體、已載入模型、拒絕並記錄 | 打開系統狀態 |
   | 批次辨識（ADR 017） | 說明（照片在功能頁上一次選一批） | 打開批次辨識 |
   | 並排比較（ADR 017） | 兩件不同的欄位（前 6 個，名稱與編號除外）；只提到一件時請到比較頁選另一件 | 看完整比較表、差異摘要與匯出 |
   | 附了照片 | 依辨識結果 | 再加「看照片辨識細節」；比對不到時是這個加上「拍照建檔：這是一幅畫／一張圖紙」（`/artworks/intake?image=`、`/drawings/intake?image=`，ADR 013；圖紙那顆只給能用工廠領域的身分）（沒收錄的畫作做色彩分析、沒收錄的圖紙重建 3D）；認出是畫作時再加「和另一張照片比對」（`/photo-diff?a=`，附的照片當照片 A，見 `012-image-alignment-compare.md`） |

   第 1、2 段擋下、降級「查無資料」、閒聊短路、要澄清、超出範圍都不給按鈕。附照片時「繼續問」「開始 3D 重建」帶 `?image=`。
4. **按鈕不能透露看不到的圖紙**：指定圖紙的按鈕只在 `auth.filter.doc_id` 是那張圖紙、且 `doc_level` 不是 null
   （第 1 段確認它在憑證權限內；看不到的文件後端不回等級）時才給。業務問〈連接法蘭〉在第 6 段降級「查無資料」，
   回答下方也不會出現「打開〈連接法蘭〉圖紙」。庫存查詢走工廠資料庫的權限、不知道圖紙等級，所以不給圖紙按鈕。
5. **耗時的功能仍不自動執行**：3D 重建（約 1–2 分鐘、載入約 6 GB 模型）按「開始 3D 重建」才開始；
   排程會寫回資料庫，打開排程頁後按「開始排程」才求解。
6. **對話不中斷**：Layout 一直掛著智慧助理（到功能頁時只是 `hidden`），回來時對話、串流中的回答、捲動位置都還在，
   不會重新呼叫 `/agent/route`。對話中切換身分會留一行「已切換身分為〈…〉」；切換身分會讓所有查詢重抓，
   但舊的搜尋結果維持當時那個身分看到的內容。「新對話」清空。
7. **對話式版面**：新的一輪在最下面、輸入框固定在畫面底部（📷 附照片）；示範句、試試防護架構、展示腳本在還沒對話時
   攤在首頁，對話中從輸入框下方「示範句與展示腳本」叫出。

## 取捨
- 「統一入口」是介面不提供功能切換，不是拿掉功能：功能頁仍可直接打網址進去，權限照舊由 API 層檢查
  （README 展示腳本第 33 項）。
- 對話只存在這個瀏覽器分頁的記憶體，重新整理就清空（和之前的智慧助理頁相同）。
- 追問仍沒有上下文：`/agent/route` 一句一句判斷，「這幅畫」要靠附照片或說出畫名；要對同一幅畫、同一張圖連續追問，
  按「繼續問這幅畫／這張圖」到問答頁。
- 對話頁一直掛著，背景會多一點記憶體與輪詢；首頁的「拒絕並記錄」改成打開才抓。
