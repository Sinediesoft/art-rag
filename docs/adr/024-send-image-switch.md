# ADR 024：問答可以設定不附圖（已辨識、檢索開著時）

- 日期：2026-10-05
- 狀態：採用（開關；預設維持送圖，要不要改預設由組員依 GTX 1650 的數字決定）
- 來源：Issue #2（Anton）

## 背景
4 GB 顯卡（GTX 1650）上問答很慢：首字 P95 20.8 秒、總計中位數 25.1 秒。`qwen3-vl:4b-instruct` 約 4.24 GB，
只有一半在 VRAM（`53%/47% CPU/GPU`），帶圖時只有 5–6 tok/s。

`chat_service` 每題都附一張長邊 1024 px 的圖（上傳照片 → 圖紙原圖 → 畫作原圖），約 1,070 token；
但 `answer_v2`／`drawing_v2` 第 1 條是「只根據下方參考資料回答」，答案本來就來自段落與作品卡。
Anton 在 GTX 1650 實測：不送圖 prompt 1,874 → 814 token，輸出 5.5 → 8.5 tok/s。

## 決定
加開關，**只在「畫作／圖紙已辨識或已指定、檢索開著」時**不送圖：
- 優先順序比照段落篩選：請求的 `send_image` ＞ `.env` 的 `SEND_IMAGE` ＞ `models.yaml` 的 `chat.send_image`（預設 `true`）
- **照樣送圖**：關檢索的對照組（`use_retrieval=false`，README 的檢索增益靠它量；A1 雲端對照組也是關檢索）
- 走到組 prompt 時畫作／圖紙一定已經辨識或指定（辨識不到在第 1 步就回 `NOT_IN_KB`），所以不會有「還不知道是哪幅就不送圖」
- 3D 重建讀尺寸、3D 重建對照組不在問答流程裡，不受影響
- SSE `done.image_sent` 記這題有沒有附圖；`egress.images` 本來就會反映雲端對照組少送了圖
- `make eval-send-image`（`run_eval.py` 的 `hybrid_img`／`hybrid_noimg`）明確指定兩邊，不受主機設定影響

## 結果（5070 Ti、Qwen3-VL 8B Q4，31 題：畫作 25＋圖紙 6，含 12 題干擾段落題，`eval/runs/20261005T061328-7c09`）

| | 附圖（預設） | 不附圖 |
|---|---|---|
| 問答／引用正確率 | 96.8%／96.8% | **100%／100%** |
| 干擾段落題被帶偏 | 1/12 | 0/12 |
| P95 首字 | 1.92 秒 | **1.21 秒** |
| P95 總計／中位數 | 2.60／1.81 秒 | 2.10／1.54 秒 |

- 兩邊只差一題：〈谿山行旅圖〉誰發現簽名——附圖時把兩種說法湊成「分別由李霖燦與張大千發現」，
  不附圖時寫出「參考資料的說法不一致」。**只差 1 題，不能說附圖會讓模型更容易被帶偏**，比較像隨機差異。
- 3 題顏色題兩邊都答對：答案來自建索引時算好的「色彩分析」段落（ADR 010），不靠看圖。
- 5070 Ti 上 8B 全部在 GPU，所以只快 0.7 秒；**主要受益的是 GTX 1650**，請 Anton 用 `make eval-send-image` 補那台的數字。

## 注意
- 問題要看畫面細節、但段落裡沒寫的（例如「右邊的人穿什麼顏色？」），不附圖時模型會照第 1 條規則回答「知識庫中沒有」。
  這是規則要的行為，但使用者感受不同；目前評估題沒有這一類，D 補題時可以加。
- 預設維持送圖。改預設要先看 GTX 1650 的結果，並在共用層變更紀錄通知。
