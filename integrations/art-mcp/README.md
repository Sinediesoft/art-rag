# art-mcp：臺灣民間藝術知識庫的 AI 助理接口（MCP）

> ArtRAG 小組專題中，**Door 的個人 AI 模組**。
> 讓 Claude 等 AI 助理透過 **MCP（Model Context Protocol）** 直接查詢知識庫，回答附原文出處與授權。
> 網站上的說明頁：`/mcp.html`（側欄「AI 助理接口（MCP）↗」）。給組員 AI 的整合說明：[`INTEGRATION.md`](INTEGRATION.md)。

---

## 1. 一句話成果

自己蒐集 20 件冷門的臺灣民間藝術資料（版印、交趾陶、剪黏），自建中文語意搜尋，包成 MCP Server 讓 Claude 呼叫。用 30 題 A/B 對照評估：

| 指標（人工複核後） | 不接 MCP | 接上 MCP |
| --- | --- | --- |
| 關鍵字全部答對 | 5/26（19%） | **25/26（96%）** |
| 回答附知識庫出處網址 | 0/26（0%） | **24/26（92%）** |
| 知識庫沒有的題目，老實說查不到 | 4/4 | 4/4 |
| 疑似編造的網址 | 0 | 0 |

**結論**：沒接 MCP 的 Claude 本來就很少亂編，不知道就說不知道。所以 MCP 的價值是「**答得出來，而且附有出處**」，不是「從亂編變成不亂編」。

---

## 2. 為什麼做這個

- **問題**：通用 AI 對冷門的在地文化（例如褒忠祠陳天乞的交趾陶、臺史博的版印彩紙）幾乎答不出來，就算答了也沒有出處。
- **使用者**：導覽志工（要準備導覽稿）、商品設計師（想用圖案，在意授權）、對廟宇有興趣的學生和遊客。
- **為什麼用 MCP**：小組網站是給「人」用的介面；MCP 是給「AI 助理」用的標準接口。接上之後，任何支援 MCP 的 AI 助理（Claude 桌面版等）都能直接查這個知識庫，不用另外開發聊天介面。

---

## 3. 系統架構

```
使用者（自然語言提問）
   ▼
Claude 桌面版（AI 助理）── 讀「工具說明」，自己決定要叫哪個工具
   ▼  MCP 協定，stdio 管線
server.py（MCP Server）
   ├ 4 個工具：search_passages／search_artworks／get_artwork／list_artworks
   ├ 1 個資料：artworks://catalog（館藏清單）
   ├ 1 個範本：tour_script（導覽稿）
   └ 每次呼叫寫進登記簿 logs/tool_calls.jsonl
   ▼
search.py（自建語意搜尋）
   切段成索引卡 → 中文向量（bge-small-zh）→ 名字加分 → 門檻擋離題 → 去重
   ▼
kb/artworks/（跟小組系統同一份資料，23 件、97 張索引卡）
   ▲
   └ 只回傳「原文段落＋出處＋授權」，回答由 Claude 撰寫
```

設計重點：**工具只找卡、不寫答案**。
- 筆電（8 GB、無獨立顯卡）不用跑大模型。
- 出錯時分得出是「搜尋錯」（卡沒找到），還是「回答錯」（卡對、講錯）。

## 4. 使用的技術（完整清單）

| 類別 | 技術 | 用在哪裡 |
| --- | --- | --- |
| AI 接口 | **Model Context Protocol**（Python `mcp` 2.3.0，2.x 新寫法）、stdio 傳輸 | `server.py`：4 工具＋1 資料＋1 範本 |
| 檢索增強生成 | **RAG**：先檢索原文段落，再交給 LLM 根據段落回答 | 整體架構 |
| 文字向量 | **fastembed** 0.9.0＋**BAAI/bge-small-zh-v1.5**（512 維、約 90 MB、ONNX、CPU 可跑） | `search.py` |
| 相似度計算 | 餘弦相似度（numpy） | `search.py` |
| 混合排序 | 語意分數＋**關鍵字加分**（作品名／人名對到每個 +0.05，上限 0.10） | 解決模型分不出相近名字（貢寶圖 vs 富貴圖） |
| 拒答門檻 | 相似度門檻 0.60（從 20 題有答案＋5 題沒答案實測決定） | 擋掉離題問題 |
| 近重複去除 | 97% 以上相同的段落只算一次 | 館方資料在 4 筆重複出現 |
| 切段 | 一張索引卡只講一件事（主題段落） | `build_index.py` |
| 工具說明設計 | 「適用情境／禁忌情境與替代方案／硬性規範」格式 | 控制 AI 選哪個工具、query 要帶什麼 |
| 錯誤處理 | 找不到時回傳「下一步該做什麼」（例如改用 list_artworks） | Claude 會照著做，不會放棄或亂編 |
| 可觀測性 | 結構化日誌 JSONL（工具、參數、耗時、成功與否） | 評估時對應每題用了哪些工具 |
| 資料工程 | 從文化部典藏網、國家文化記憶庫整理 20 件；符合小組 JSON Schema；逐筆人工抽查 | `kb/artworks/`（`validate_kb` 通過） |
| 授權 | CC BY 4.0／CC BY 3.0 TW；每筆帶出處網址與標示文字 | 工具回傳時一併附上 |
| 評估 | A/B 對照（只差有沒有接 MCP）、6 項自動計分、人工複核、穩定性抽查 | `eval/`、`score.py` |
| 環境 | Python 3.12、uv、版本鎖定（requirements.lock.txt）、Windows .bat 一鍵執行 | `setup.bat` 等 |
| 測試 | stdio 模擬用戶端自我檢查 27 項 | `self_check.py` |

## 6. 重要的設計決策（為什麼這樣做）

1. **為什麼做 MCP，不在網站做聊天機器人？** MCP 是開放標準，一次做好，任何 AI 助理都能用。改小組網站的聊天，要動權限控管，風險高。
2. **為什麼自帶搜尋，不直接用小組後端？** 筆電跑不動小組完整系統。自帶搜尋可以獨立展示；之後再加「連接模式」，把點單轉給小組後端。
3. **為什麼選小模型 bge-small-zh？** 中文表現好、CPU 就能跑、檔案小；評估顯示接上後答對率 96%，已經夠用。
4. **為什麼回答交給 AI，工具只回原文？** 筆電跑不動大模型；而且這樣能把「搜尋錯」和「回答錯」分開查。
5. **為什麼不做第 5 層（網站聊天改走 MCP）？** 要改小組七段權限控管，風險大於效益，列為未來擴充。

## 7. 評估怎麼做

- **考卷**：30 題，分四種題型：一般 6、冷門細節 15、知識庫沒有的 4、陷阱題 5。陷阱題的題目裡藏了一個錯的說法，例如「祿仙手上拿著如意」，其實是福仙拿如意。
  - 評估題和調整搜尋時用的 25 題分開出，避免「拿考古題當期末考」。
  - 出題方式是先寫問題、再查答案，以導覽志工、設計師、遊客三種身分發問，降低出題偏差。
- **條件**：A 不接 MCP、B 接上 MCP。兩邊都用同一個帳號、同一個模型（Sonnet 5.5 Medium）、關閉網頁搜尋、每題開新對話。
- **計分**：用 `score.py` 自動計分，算 6 項指標：關鍵字命中、出處是否真實、該拒答有沒有拒答、不該拒答卻拒答、工具選對、參數正確。
  - 題目本身已經有的關鍵字不計分。
  - 工具呼叫用「回答檔的存檔時間」對到每一題。
- **人工複核**：改正了 1 題標準答案（資料其實有寫「一百六十八個」），修了 3 種計分誤判；改前、改後的數字都保留。
- **穩定性**：基準 10 題的條件 A 跑了兩次（不同天、不同帳號），8/10 題分數相同。
- **限制**：題目自己出、每題只跑一次、知識庫只有 23 件，結論只適用於這個知識庫。

## 8. 失敗分析（3 件）

| 案例 | 錯在哪一層 | 證據 | 原因 | 改進方向 |
| --- | --- | --- | --- | --- |
| N19 問江清露生卒年，卻說「查不到」 | 搜尋 | 「江清露的生平」分數 0.565，沒過門檻 0.60；加上廟名「北港朝天宮屋頂剪黏的匠師江清露」是 0.869 | 名字只佔長段落裡的一小句，意思被稀釋 | 把卡切得更小；名字命中時放寬門檻 |
| N23 九曲黃河陣女將，一次工具都沒叫 | 工具選擇 | 登記簿在那段時間內沒有任何呼叫；Claude 憑小說知識列出三姊妹 | 「我去褒忠祠拜拜看到…」的現場描述不在工具說明的適用情境裡 | 工具說明加入宮廟名、現場看到的作品等情境 |
| N18 陶偶數量，被誤當成「知識庫沒有的」題 | 考卷（驗證方法） | 資料寫「一百六十八個」，出題核對時只搜了阿拉伯數字 | 只用一種寫法就判定「查不到」 | 用多種寫法搜（阿拉伯、中文數字、別名），再實際用工具查一次 |

## 9. 檔案說明

| 檔案 | 用途 |
| --- | --- |
| `server.py` | MCP Server：4 工具、1 資料、1 範本、登記簿 |
| `search.py` | 讀資料、切段、向量、名字加分、門檻、去重 |
| `build_index.py`／`.bat` | 建索引（第一次會下載向量模型） |
| `self_check.py`／`.bat` | 像 Claude 一樣用 stdio 連上 Server，檢查 27 項 |
| `test_search.py`、`diag_search.py` | 搜尋小測驗、找錯原因的診斷實驗 |
| `score.py`／`.bat` | 評估計分（A/B 對照、6 項指標、HTML 成績單） |
| `exam_helper.py`、`exam_A.bat`、`exam_B.bat` | 考試小幫手：遞題目、收回答、記時間（不呼叫 Claude） |
| `setup.bat` | 安裝 Python 3.12 環境與固定版本套件 |
| `check_claude_config.*`、`fix_claude_config.*`、`remove_hello.*` | 檢查、修改 Claude 桌面版設定檔（Store 版位置） |
| `keywords.txt` | 名字加分用的人名、廟名清單 |
| `eval/` | 考卷、A／B 回答、計分結果（`results/report.html`） |
| `docs/資料抓取紀錄.md` | 20 件資料從哪裡抓、怎麼整理 |

**資料位置**：放在小組 repo 時，直接讀 `kb/artworks/`；放在個人資料夾時，讀自己的 `data/artworks/`。
